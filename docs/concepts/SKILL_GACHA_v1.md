# 新企画：スキルガチャ無双（仮題）v1（2026-11-27）

`CONCEPT_PROPOSALS_v1.md` の案 A をもとにした。「ハズレスキル」は印象が悪いので、**ガチャで引いたスキルで敵をなぎ倒す爽快感**を売りにする。名前・技名はすべて自作（仮）。

## 1. 一言で

> 迷宮でスキル玉を集め、祠で開けて（ガチャ）、引いたスキルを組み合わせて敵の群れを一掃する

## 2. 1 周の流れ

1. 迷宮に入ると、弱い敵が**群れで**出てくる（無双の手応えは「数の多さ × 一撃で吹き飛ぶ」で作る）
2. 倒すとスキル玉が落ちる。持って祠まで帰る。運んでいる途中に他の人に叩かれると、玉を落とす
3. 祠で玉を開ける＝ガチャ。レア度で演出が変わる（光の色、画面の揺れ、全員への通知）
4. スキルを付ける。付けられる量には上限コストがある（Phase 0 の「付与」と同じしくみ）。組み合わせで必殺技が変わる
5. 祠に置いたスキルは、放置しているあいだも少しずつ育つ（経験値が貯まる）
6. 強くなると、もっと深い階に行ける。迷宮の玉は 15 分ごとに一斉に入れ替わる

## 3. 爽快感の作り方（ここにお金と手間をかける）

| 要素 | 内容 |
| --- | --- |
| 数 | 1 回の必殺技で 10〜30 体が吹き飛ぶ |
| 数字 | 大きなダメージの数字、連続撃破の数（「47 体撃破！」） |
| 見た目 | レアなスキルほど、エフェクトが大きく派手になる。周りの人にも見える（見せびらかし） |
| 成長の実感 | 前は 3 発かかった敵が 1 発になる。階ごとに「推奨の強さ」を出す |
| ガチャの瞬間 | 開ける前のため、レア度で変わる光、最高レアは全サーバーに通知 |

## 4. 課金の考え方（Phase 0 とは別の企画なので、ここでは検討してよい）

- ガチャは**遊んで手に入る玉が主役**。課金しないと強くなれない作りにはしない（1 人でも遊べる・続けられる）
- 課金の候補：玉を開ける速さ 2 倍、持てる玉の数を増やす、見た目だけのエフェクトの色違い、祠の飾り
- **Robux で引けるガチャを作る場合の決まり**（Roblox 公式、2026 年 10 月更新）
  - 出るものすべてと、その確率の数字を表示する。確率を上げるアイテムを使っているときは、上がったあとの確率を表示する
  - `PolicyService` の `ArePaidRandomItemsRestricted` が true の人には、有料ガチャを使わせない（英国の 18 歳未満など）。使わないと、英国の 18 歳未満にはゲーム全体が表示されなくなる
- 確率はサーバーで決め、10〜20 万回のシミュレーションで確かめる

## 6. AI の役割分担と、どれだけ必要か

### 結論

**課金したくなるかどうかは、3D モデルの出来よりも「エフェクト・演出・UI・手触り」で決まる。** プレイヤーのキャラクターは各自の Roblox アバターなので、3D で作るのは敵・ボス・祠・迷宮の小物だけでよい。

| 分野 | 担当 | 手間の目安 | 課金への効き方 |
| --- | --- | --- | --- |
| ゲームのしくみ、ガチャ、戦闘の手触り、保存、確率の表示 | Claude Code | 約 40% | 土台。ここが悪いと何をしても続かない |
| エフェクト・ガチャ演出・UI・アイコン | Claude Code（スクリプト）＋画像生成（テクスチャ・アイコン）＋ダイスケさんの目 | 約 30% | **一番効く**。人は「派手なスキル」と「引いた瞬間」にお金を払う |
| 敵・ボス・ペット的なキャラクター | Tripo | 約 15% | 中。敵が群れで出るので、軽くて見分けやすいことの方が大事 |
| 迷宮・祠・小物 | Codex または Studio の生成機能 | 約 10% | 小〜中。雰囲気づくり |
| 効果音・BGM | Creator Store の音（ライセンスを確認） | 約 5% | 小さいが、ないと爽快感が半減する |

数字は目安（調べた資料ではなく、ここまでの経験からの見積もり）。

### 講座の分け方との違い

- **Codex は必須ではない**。Codex はプログラムを書く AI なので、3D 素材を作るときは「Blender を動かすスクリプトを書かせる」使い方になる。同じことは Claude Code でもできる。また、Roblox Studio の MCP には、メッシュ・素材・テクスチャ・手続き型モデルを作る機能と、アバターのリグを自動で付ける機能、アニメーションを作る機能がある。まずはそちらを試し、足りなければ Codex を足す
- **Tripo は敵・ボスに使う**。主人公には使わない
- **一番大事なのは「見た目の決まり」を 1 か所にまとめること**。AI を分けると、絵柄がばらばらになりやすい

## 7. 連携の手順

```
① 素材の一覧（docs/ASSETS.md）
     ↓ Claude Code が一覧から、Tripo などに渡す指示文を作る
② 作る：Tripo（敵・ボス）／Studio の生成機能・Codex（小物）／画像生成（アイコン・テクスチャ）
     ↓ FBX か glTF で書き出す
③ 確かめる：三角形の数、大きさ、テクスチャ
     ↓
④ Roblox に上げる：グループ名義で（Studio の 3D インポーター、または Open Cloud）
     ↓ 素材 ID を Defs に書く
⑤ Claude Code が Studio MCP で配置し、プレイテストと画面の撮影をする
```

1. **見た目の決まりを先に作る**（`docs/STYLE_GUIDE.md`）：絵柄（例：トゥーン調・太い輪郭）、色の決まり（レア度ごとの色）、大きさ（人型は約 6 スタッド）、三角形の上限（敵 1 体 5,000 前後、ボス 10,000 まで）
2. **素材の一覧を作る**（`docs/ASSETS.md`）：名前、種類、担当の AI、大きさ、三角形の上限、状態（未作成／作成済み／アップロード済み）、素材 ID
3. **Claude Code に指示文を書かせる**：一覧と見た目の決まりから、Tripo に入れる文章や参考画像の条件を作る。毎回同じ書き出しにして、絵柄をそろえる
4. **Tripo で作る**：生成 → 軽いメッシュ（Smart Mesh）にする → 敵はリグを付ける → FBX で書き出す。Tripo の出力したリグが Roblox でそのまま動くかは、まだ確かめていない。動かない場合は、Studio の自動リグ機能を使う
5. **Studio に取り込む**：Studio の 3D インポーター（ファイル → インポート）で取り込み、プレビューで大きさとテクスチャを確かめる。数が増えたら、Open Cloud でまとめて上げる（Claude Code から実行できる）
6. **グループ名義で上げる**：あとでチームや会社に移すときに困らないようにするため
7. **コードからは素材 ID で参照する**：ID は Defs にまとめ、コードの中に直接書かない（Phase 0 の Config・Defs と同じ考え方）
8. **Claude Code が Studio MCP で確かめる**：配置、当たり判定、数を出したときの重さ（敵 30 体を出したときのフレーム数）、画面の撮影
9. **Git に残す**：スクリプトは今までどおり Rojo で同期する。モデルは `.rbxm` に書き出して `assets/` に置くかどうか、決める必要がある

1. 正式な題名の方向（日本語中心か、英語中心か。Roblox は海外の遊び手が多い）
2. Robux で引けるガチャを入れるか、ガチャは遊んで手に入る玉だけにして、課金は速さ・見た目にするか（後者の方が規則と炎上の心配が少ない）
3. 新企画のリポジトリを分けるか、このリポジトリで Phase 0 の資産を移して続けるか
